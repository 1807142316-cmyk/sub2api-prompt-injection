# 提示词注入

管理员可在侧栏“提示词注入”中编辑前置提示词、后置提示词和模型专用后置内容。编辑器支持放大编辑、正文查找、字数与行数统计、草稿预览及未保存提醒。预览展示当前草稿的分层结果，不代表已经保存，也不包含任务 Skills 的完整选择和正文。

## 分组设置

每个分组有三种方式：

- **继承全局**：不保存该组的独立配置，按正常优先级选择配置。
- **使用独立提示词**：保存该组整份前置、后置及模型配置。用户或客户端专属配置仍可优先生效。
- **不注入提示词（含 Skills）**：该组跳过本页的前置、后置和自动全局、分组 Skills。用户或客户端专属配置不能覆盖这一选择；即使本页总开关关闭，这项选择仍生效。

分组以认证后的客户端 API Key 所绑定的原始分组为准。请求正文、客户端自报的分组编号以及后续路由切换都不能改变此作用域。

“不注入”只控制本页分层提示词和自动 Skills。客户端原本提交的指令仍保留，协议适配器原有的默认指令和兼容处理仍按原设置执行。

## 优先级与开关

普通配置按 **API Key > 用户 > 分组 > 全局默认** 选择整份配置，不逐字段合并。选中配置中的空白内容不会从低优先级配置补齐。

用户或 API Key 专属配置停用时，不再回退到分组或全局默认，但自动 Skills 仍按原规则运行。本页总开关关闭时，只停止前置和后置分层；自动 Skills 仍按原规则运行，分组“不注入”除外。

删除专属配置会恢复继承。正文的空格、制表符及换行会按原文保存。

## 模型专用后置

后置内容按精确模型名称、`*`、通用后置内容的顺序匹配。模型专用项明确选择“不追加”时，空内容会覆盖其他后置规则，不会自动回退。

使用模型别名时，应核对实际传入注入入口的模型名称。现有 HTTP 组合分组路径会先做模型映射，实时连接首帧路径的处理时点可能不同，预览不能替代客户端实测。已经建立的实时连接需要在保存配置后重新连接。

## 兼容与构建

配置继续保存在原有 `instruction_layers` 设置中。旧配置缺少 `groups` 字段时按空分组配置读取，无需新增数据库迁移，也不会自动填入任何提示词正文。

沿用仓库根目录的上游 `Dockerfile`、依赖锁文件和 README 构建流程。前端需要构建后嵌入后端；不要将本地 `node_modules`、编译缓存或已生成的前端 `dist` 提交到源码仓库。构建定制发行版时，应使用明确的自定义版本号。
